# 知识库

知识库保存**用户给的原文**：工作区目录里的文档被解析、切成带出处的块，模型可以
用 `qq_kb_search` 按需检索，必要时每回合自动带上几块证据。

它和另外两套东西的分工：

| 系统 | 存什么 | 什么时候用 |
|---|---|---|
| 记忆（`memory.v2`） | 从聊天里沉淀的一句话事实 | 自动注入、会衰减、有反思审核 |
| **知识库** | 用户放进目录的文档原文 | 按需检索、带引用、不衰减 |
| 技能 | 做事步骤（SKILL.md） | 显式加载或 `/名字` 触发 |

## 快速开始

1. 把资料放进工作区（`workspacePath`）下的 `inbox/`、`downloads/` 或 `kb/raw/`；
2. 后台「知识库」页点「立即扫描」（或者等 `kb.pollMinutes` 的定时扫描）；
3. 模型需要资料时会调用 `qq_kb_search`，回答里带
   `[知识库·标题·标题路径·第 N 段]` 这样的出处。

支持的格式：

- **原生解析**：md / txt / html / json / csv / rst / log；
- **Docling（可选）**：pdf / docx / pptx / xlsx / odt / epub / 图片。
  配置 `kb.doclingUrl` 指向本机 `docling-serve`（如 `http://127.0.0.1:5001`）。
  没配时 PDF/Office 会以「解析失败：需要配置 Docling」登记在后台；**图片直接跳过**
  （下载目录里的图往往成百上千，不 OCR 就没有索引价值）。

## 配置

后台「知识库」页（`kb` 段）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉后不扫描、不注册工具；后台仍可查看已有文档 |
| `dirs` | `inbox,downloads,kb/raw` | 要扫描的工作区相对目录（逗号分隔） |
| `maxFileBytes` | 8 MB | 单文件上限，超了跳过并记录原因 |
| `doclingUrl` | 空 | docling-serve 地址；空 = 只解析文本格式 |
| `pollMinutes` | 10 | 定时扫描间隔；0 = 只手动触发 |
| `injectTop` | 0 | 每回合自动注入几块证据；0 = 只用工具 |
| `injectChars` | 400 | 自动注入的字符上限 |
| `vectorWeight` | 0.6 | 向量相对关键词的权重（需打开记忆的向量检索） |
| `scopes` | 空 | 集合可见范围，JSON：`{"inbox":["group-123"]}` |

`scopes` 里没有的集合对**所有房间**可见；有白名单的集合只对列出的房间可见
（系统回合 `room=null` 看不见它们）。

## 摄取与存储

```
文件 → 读一次字节 → sha256 → 哈希没变就跳过
     → 解析（HTML 转 Markdown；Docling 可选）
     → 标题感知分块（标题路径 + 行号 + 页码）
     → 旧块归档 → 新块写入
```

- 存储在工作区 `kb/`：`documents.jsonl`（文档表）、`chunks.jsonl`（块表）、
  可选的 `vec.bin` + `vec-index.json`（向量，格式与记忆相同）；
- 追加式写入、定期压缩；块是**软删除**（`archived: true`），历史可查；
- 文件变小/被删除时旧块归档、不再参与检索；磁盘文件本身不会被删；
- 串行处理，单个文件失败不会中断整轮，原因写在文档表里。

## 检索

`qq_kb_search`：

- 不传 `query`：列出当前房间可见的集合与文档；
- 传 `query`：关键词（中文二元组 + IDF，标题命中加权）+ 向量（打开记忆向量后）
  两路融合，返回最多 10 块原文与引用；
- 房间来自 `exec.agent.id`（`qq-group-123` → `group-123`），与技能可见范围同一套键。

自动注入（`injectTop > 0`）与记忆证据**各占一段**：记忆是"我记得"，知识库是
"资料里写着"，两段都命中就都带上；都没命中时组包与从前逐字节一致。

## 自我学习闭环

所有自动写入都保持「候选 → 审核」：

- **资料 → 事实**：夜间记忆任务从知识库/工作区的原文抽事实（候选态，人工审核）；
- **事实 → 方法**：后台「记忆审核」页对候选点「写成技能」，写入技能**待审区**
  （`SKILL.md` + 来源 metadata），到「技能」页确认后才启用；
- **对话 → 资料**：用户发文件时放进 `inbox/`；明确说"记住这个"时进记忆。

## 评测

```bash
npm run build
npm run eval:kb            # 合成 16 题：hit@1 / hit@5 / MRR / p95
node eval/kb/run.mjs --enforce   # 门槛不达标时退出码 1
```

合成语料在 `eval/kb/corpus.mjs`；测的是线上同一套摄取 + 分块 + 检索代码。
接上真实资料后，建议把常见问题补进 `QUESTIONS`，看命中率有没有回退。

## 已知限制

- 中文按二元组检索，不做分词：专有名词与短查询表现好，长句里跨词边界的噪声靠
  IDF 与虚词表压住；
- 标题感知依赖 Markdown 标题（`#`）。纯文本没有标题时整篇按长度切；
- 向量索引是暴力余弦（几千块量级足够）；超过几万块需要换索引结构；
- Docling 是可选 sidecar，不在本仓库内；没有它就读不了 PDF/Office。
